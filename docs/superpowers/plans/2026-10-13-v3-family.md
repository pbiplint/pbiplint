# v3 Power Query Family Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pull request 3 of v3 ([#78](https://github.com/pbiplint/pbiplint/issues/78)): Power Query becomes a rule family of its own, `powerquery`, through core, the CLI, and the site. The rules index gets a clickable Show filter. `MINIMIZE_POWER_QUERY_TRANSFORMATIONS` is its first member, moved onto Microsoft's parser as a recorded deviation from Tabular Editor.

**Architecture:** Core gains the fourth `Rule.layer` value first, with no rule on it, so every output can be tested on a made-up rule. The site then learns the value: one shared module, `packages/web/src/layers.ts`, holds the label map and the one visibility rule that the rules index and the results page both follow. The results filter widens next. Then the shipped rule moves onto the parser, its page and its capture's deviation with it, and the CLI's columns widen. The rules index filter comes last, because its end-to-end test needs a published Power Query page. A final task measures the bundle and runs the corpus diff.

**Tech Stack:** TypeScript (core, CLI, site), `@microsoft/powerquery-parser` 2.0.0 (already pinned by pull request 2a), Vite 8, Vitest, happy-dom, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-12-pbiplint-v3-power-query-layer-design.md`, sections 9.7, 10.1, 10.2, 10.3, 11.4, 11.7, and 12.2 item 3. Read 9.7, 10.1, and 10.2 before starting.

## Where this plan reads the spec narrowly

- **The results e2e check (spec 11.7) uses shelfmart, not the sample.** The sample (messy-sales) has no M that the shipped rule reads, so in this pull request its results show no Power Query group. Shelfmart's partitions call `Table.AddColumn` and `Table.NestedJoin`, so its results gain a Power Query group here. Pull request 4, where `LOCAL_DRIVE_PATH` fires on the sample, adds the sample assertion.
- **The page's Quirks lose three lines, not four.** Spec 9.7 says "the four lines about substring matching". The page has four Quirks bullets, but one ("Only partitions whose source type is M are read") is about scope, not matching, and stays true. The three matching bullets go.
- **The label map lives in the shared module, not in `pages.ts`.** Spec 10.1 puts it "beside `RULE_LAYERS`" and spec 10.2 has the results page and the rules index share one visibility function. The results page runs in the browser and cannot import `pages.ts` (a build module), so `RuleLayer`, `RULE_LAYERS`, the label map, and the visibility function move together into `packages/web/src/layers.ts`, and `pages.ts` imports them. They stay beside each other, and nothing from core is imported.
- **A native query is read from a record written in place.** Spec 9.7 says "a `Query` field in the options record of a database connector". The rule reads any record literal among the connector's arguments (each connector takes at most one), and does not follow a name to a record bound elsewhere. Tabular Editor's text match never did either, and no corpus example in the research needs it.
- **With every box unchecked, the address reads `?layer=`.** Spec 10.2 says an empty value opens with every box checked, so a reload of that address shows every rule. The live count still reads "Showing 0 of N rules" before the reload. This is the spec's rule followed literally; no special case is added.

Create `packages/web/src/layers.ts`:

```ts
/**
 * A rule's layer as the site names it, the site's copy of core's `Layer`: a file family, `project`
 * for a rule that reads both, or `powerquery` for a rule that reads the Power Query M a model's
 * files hold (v3 spec, section 10.1). The copy is deliberate for the reason CATEGORY_ORDER gives
 * in build/pages.ts: the site build imports nothing from core. The rules index (build/pages.ts and
 * rules-filter.ts) and the results page (results/render.ts) both read this module, so the two name
 * and filter a layer alike.
 */
export type RuleLayer = "model" | "report" | "project" | "powerquery";

/** Every layer a page may declare, and the list the error names when a page declares another. */
export const RULE_LAYERS: readonly RuleLayer[] = ["model", "report", "project", "powerquery"];

/**
 * How the site writes a layer on a tag, a meta line, and a filter box: Power Query by its product
 * name, every other layer by its own word, as before v3.
 */
export const LAYER_LABEL: Record<RuleLayer, string> = {
  model: "model",
  report: "report",
  project: "project",
  powerquery: "Power Query",
};

/** The families a reader can filter by, in the order their boxes show. `project` is not one. */
export const FILTER_LAYERS = ["model", "report", "powerquery"] as const;

/** A filter box's label, in title case like the severity and category boxes: "Power Query". */
export function boxLabel(layer: string): string {
  const label = LAYER_LABEL[layer as RuleLayer] ?? layer;
  return label.charAt(0).toUpperCase() + label.slice(1);
}

/**
 * Whether a rule (on the rules index) or a group (in the results) on `layer` shows, given the
 * filter boxes `present` and the ones `checked`. A family shows while its box is checked, or when
 * it has no box. A `project` rule reads both file families, so it shows while the Model or the
 * Report box is checked, or when neither is present; Power Query alone does not show it.
 */
export function layerShown(
  layer: string,
  checked: ReadonlySet<string>,
  present: readonly string[],
): boolean {
  if (layer === "project") {
    const files = present.filter((l) => l === "model" || l === "report");
    return files.length === 0 || files.some((l) => checked.has(l));
  }
  return !present.includes(layer) || checked.has(layer);
}
```

```ts
  "SapHana.Database",
  "GoogleBigQuery.Database",
]);

/** A record written in place with a `Query` field. */
function hasQueryField(node: Language.Ast.TNode): boolean {
  const n = unwrap(node);
  if (n.kind !== Kind.RecordExpression && n.kind !== Kind.RecordLiteral) return false;
  return n.content.elements.some((csv) => identifierName(csv.node.key.literal) === "Query");
}

/**
 * What makes a partition's query one MINIMIZE_POWER_QUERY_TRANSFORMATIONS reports, sorted: each
 * transformation the M names, called or passed as a function value, and `<connector> Query` for a
 * database connector given a native query in its options record. Empty when the M has neither, or
 * did not parse. Read from the parsed M, so a name in a comment or a text literal does not count:
 * a documented deviation from Tabular Editor's text match (v3 spec, section 9.7).
 */
export function powerQueryTransformations(q: MQuery): string[] {
  const found = new Set<string>();
  for (const id of q.nodeIdMapCollection?.idsByNodeKind.get(Kind.IdentifierExpression) ?? []) {
    const n = nodeOf(q, id);
    if (n?.kind !== Kind.IdentifierExpression) continue;
    const name = identifierName(n.identifier.literal);
    if (TRANSFORMATIONS.has(name)) found.add(name);
  }
  for (const c of calls(q))
    if (NATIVE_QUERY_CONNECTORS.has(c.name) && c.args.some(hasQueryField))
      found.add(`${c.name} Query`);
  return [...found].sort();
}

// Read from Microsoft's parser rather than the M text: a native query counts however its SQL is
// written, and a name in a comment or a text literal does not. A documented deviation, and a
// partition whose M does not parse is left to PARSE_ISSUE.
export const MINIMIZE_POWER_QUERY_TRANSFORMATIONS = bpaRule(
  "MINIMIZE_POWER_QUERY_TRANSFORMATIONS",
  { layer: "powerquery" },
  (_model, ctx) =>
    ctx.indexes.m.queries
      .filter((q) => q.kind === "partition" && powerQueryTransformations(q).length > 0)
      .map((q) => finding.partition(q.owner as Partition)),
);
```

```ts
// The rules index's Show filter (v3 spec, section 10.2). The page lists every rule without it;
// this reveals the boxes and hides the rows of a family that is unchecked, and a category heading
// with its list once every row under it is hidden. It stores nothing: the state is the address's
// `layer` query, a comma-separated list of families, rewritten with replaceState as the boxes
// change, so a copied link opens what the reader sees and Back is not filled with filter states.
import { layerShown } from "./layers.js";

const form = document.querySelector<HTMLFieldSetElement>("#rules-filter");
if (form) {
  const boxes = [...form.querySelectorAll<HTMLInputElement>('input[type="checkbox"]')];
  const present = boxes.map((b) => b.value);
  const rows = [...document.querySelectorAll<HTMLElement>(".rule-list > li[data-layer]")];
  const lists = [...document.querySelectorAll<HTMLElement>(".rule-list")];
  const count = form.querySelector<HTMLElement>(".rules-shown");

  // A missing, empty, or wholly unknown value checks every box; an unknown name among known ones
  // is ignored.
  const named = (new URLSearchParams(location.search).get("layer") ?? "")
    .split(",")
    .filter((l) => present.includes(l));
  for (const b of boxes) b.checked = named.length === 0 || named.includes(b.value);

  const apply = (): void => {
    const checked = new Set(boxes.filter((b) => b.checked).map((b) => b.value));
    for (const row of rows) row.hidden = !layerShown(row.dataset.layer ?? "", checked, present);
    for (const list of lists) {
      const empty = [...list.children].every((li) => (li as HTMLElement).hidden);
      list.hidden = empty;
      const heading = list.previousElementSibling;
      if (heading instanceof HTMLHeadingElement) heading.hidden = empty;
    }
    if (count)
      count.textContent = `Showing ${rows.filter((r) => !r.hidden).length} of ${rows.length} rules`;
    // Every other query parameter is kept; the plain /rules/ stays the default.
    const params = new URLSearchParams(location.search);
    params.delete("layer");
    const rest = params.toString();
    const layer =
      checked.size === boxes.length
        ? ""
        : `layer=${boxes.filter((b) => b.checked).map((b) => b.value).join(",")}`;
    const url = new URL(location.href);
    url.search = [rest, layer].filter(Boolean).join("&");
    if (url.href !== location.href) history.replaceState(history.state, "", url);
  };

  // The count is written before the boxes appear, so the live region does not announce the
  // page's opening state.
  apply();
  form.hidden = false;
  form.addEventListener("change", apply);
}
```

```ts
// MINIMIZE_POWER_QUERY_TRANSFORMATIONS on the parser against the text match it replaced (v3 spec,
// sections 9.7 and 11.4): for every M partition in the corpus, whether the old patterns match and
// what the parsed M names, with each difference given its reason. Imports the worktree's code by
// the working directory, since .superpowers is a link into another checkout.
// Usage, from the repository root:
//   npx tsx .superpowers/sdd/2026-10-13-v3-family/minimize-diff.mts <corpus dir>
import { readdirSync, readFileSync } from "node:fs";
import { join, relative } from "node:path";

const [corpus] = process.argv.slice(2);
const core = await import(join(process.cwd(), "packages/core/src/index.ts"));
const { powerQueryTransformations } = await import(
  join(process.cwd(), "packages/core/src/rules/microsoft-bpa/tables.ts")
);

// The substrings the rule matched before this pull request, verbatim.
const OLD = [
  "Table.Combine(",
  "Table.Join(",
  "Table.NestedJoin(",
  "Table.AddColumn(",
  "Table.Group(",
  "Table.Sort(",
  "Table.Pivot(",
  "Table.Unpivot(",

  "Table.Distinct(",

  "Odbc.Query",
];

const roots: string[] = [];
const walk = (d: string) => {
  for (const e of readdirSync(d, { withFileTypes: true })) {
    if (!e.isDirectory() || e.name === ".git" || e.name === "node_modules") continue;
    const p = join(d, e.name);
    if (e.name === "definition" && /\.(SemanticModel|Dataset)$/.test(d)) roots.push(p);
    else walk(p);
  }
};
walk(corpus!);
const tmdls = (d: string): string[] =>
  readdirSync(d, { withFileTypes: true }).flatMap((e) =>
    e.isDirectory() ? tmdls(join(d, e.name)) : e.name.endsWith(".tmdl") ? [join(d, e.name)] : [],
  );

type Reason = "gained: native query" | "gained: name the old patterns missed" | "lost: does not parse" | "lost: match only in a comment or literal" | "unexplained";
const by = new Map<Reason, { n: number; models: Set<string>; repos: Set<string>; examples: string[] }>();
const note = (reason: Reason, model: string, example: string) => {
  const e = by.get(reason) ?? { n: 0, models: new Set(), repos: new Set(), examples: [] };
  e.n++;
  e.models.add(model);
  e.repos.add(model.split("/").slice(0, 2).join("/"));
  if (e.examples.length < 5) e.examples.push(example);
  by.set(reason, e);
};

for (const root of roots) {
  const model = relative(corpus!, root);
  const files = tmdls(root).map((f) => ({ path: relative(root, f).split("\\").join("/"), text: readFileSync(f, "utf8") }));
  const m = core.buildModel(files.map((f) => core.parseTmdl(f.path, f.text)));
  const index = await core.readM(m, files);
  for (const t of m.tables)
    for (const p of t.partitions) {
      if (p.sourceType !== "m") continue;
      const text = p.source ?? "";
      const old = OLD.some((s) => text.includes(s));
      const q = index.queries.find((x: { owner: unknown }) => x.owner === p);
      const hits: string[] = q ? powerQueryTransformations(q) : [];
      if (old === hits.length > 0) continue;
      const where = `${model} ${t.name}/${p.name} ${JSON.stringify(hits)}`;
      if (!old) note(hits.some((h) => h.endsWith(" Query")) ? "gained: native query" : "gained: name the old patterns missed", model, where);
      else if (q && !q.ast) note("lost: does not parse", model, where);
      else if (q) note("lost: match only in a comment or literal", model, where);
      else note("unexplained", model, where);
    }
}
for (const [reason, e] of by)
  console.log(`${reason}: ${e.n} partitions, ${e.models.size} models, ${e.repos.size} repositories\n  ${e.examples.join("\n  ")}`);
```
